# Retificação da auditoria de RLS — 13/11/2026

## Erro corrigido
O diagnóstico anterior interpretou de maneira errada as políticas `*_v161_active_*`.
No banco elas têm `permissive = RESTRICTIVE` e são combinadas por AND com
as políticas que exigem proprietário ou administrador.

O ensaio SQL com perfis autenticados reais, dentro de transações revertidas,
confirmou: ADMIN visualizou 3 auditorias, 39 revisões, 1 evidência;
AUDITOR visualizou 0/0/0 documentos de outro proprietário.
Nenhum registro, permissão ou usuário foi modificado nos testes.

A proposta de remoção dessas políticas foi **cancelada** e o arquivo de SQL
foi substituído por um aviso sem instruções de execução. **Não executar**
a proposta original. Não foi confirmado vazamento entre auditores.

## Proteções complementares
O aplicativo passa a importar automaticamente do servidor apenas auditorias
do próprio usuário, mesmo quando ele é ADMIN. Consulta de terceiros
autorizada ao administrador ocorre somente quando solicitada.
Permissões continuam aplicadas pelo Supabase; filtro do cliente é
defesa adicional, não substituto de RLS.

## Verificações ainda dependentes de navegador

simulação de desconexão; colaboração entre dois usuários e conferência do
armazenamento local após trocar de conta.

As políticas de produção permaneceram inalteradas.
